# Отчёт по нагрузочному тестированию (9 ноября 2025)

## Окружение

- Команда запуска контейнеров: `docker compose up api workers ml-pipeline`
- Миграции применены командой (внутри контейнера `api`):  
  `alembic upgrade head` (через скрипт с `script_location=/app/infra/db/migrations`)
- Тестовый профиль: `docker compose --profile perf`

## Сценарии

1. **Базовый прогон без запросов к `/nbo`**  
   
   Команда:
   
   ```bash
   docker compose --profile perf run --rm perf \
     --headless --users 1 --spawn-rate 1 --run-time 30s --stop-timeout 1 \
     --host http://api:9090 --locustfile /mnt/locust/locustfile.py
   ```
   
   - Результат: `exit code 0`
   - Обслужено 24 запроса `POST /events`, ошибок нет
   - Средние задержки: 25–27 мс (максимум 34 мс)

2. **Полный прогон с запросами к `/nbo`**  
   
   Команда:
   
   ```bash
   docker compose --profile perf run --rm \
     -e PERF_ENABLE_NBO=1 perf \
     --headless --users 1 --spawn-rate 1 --run-time 30s --stop-timeout 1 \
     --host http://api:9090 --locustfile /mnt/locust/locustfile.py
   ```
   
   - Результат: `exit code 0`
   - Обслужено 6 запросов `GET /nbo/{customer_id}`, 3 запросов `GET /nbo/{customer_id} (retry)` и 15 `POST /events`
   - Ошибок/ретраев нет
   - Средние задержки:
     - `POST /events`: 26–27 мс (максимум 33 мс)
     - `GET /nbo/{customer_id}`: медиана 25 мс, пик ~90 мс при первом обращении
     - `GET /nbo/{customer_id} (retry)`: медиана 27 мс

## Выводы

- После приведения схемы к строковым идентификаторам (`String(36)`) и применения миграций поток рекомендаций выполняется без SQL-ошибок.
- Оба сценария отработали штатно; при необходимости нагрузку и длительность можно масштабировать параметрами `--users`, `--spawn-rate` и `--run-time`.
